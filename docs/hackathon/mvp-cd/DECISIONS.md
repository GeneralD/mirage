# Decisions

One line per decision: the choice, the reason, what was turned down and why, with the source.

- [init] Base is `origin/main` 97b8a40 (0.24.1) through `hackathon/mvp-cd`: every worker PR targets it and one final PR goes to `main` on the human's word — rejected per-issue PRs to `main` because every PR bumps `version.txt` and parallel PRs would all conflict on it; the bump happens once in the final PR.
- [init] Effects run on the host; parameters need no IPC — the extension has no Metal (`scripts/check-extension-no-metal.sh`, ARCHITECTURE "No Metal in the extension process"). Rejected Mach messages, CMIO custom properties and file watching, all of which answer a problem this architecture does not have.
- [init] Parameter ABI: a `Parameters` struct generated per manifest, bound at `[[buffer(1)]]` with `setBytes`, so an author writes `params.strength` — rejected an engine-owned fixed slot array because authors would index by magic numbers and a reorder would silently change meaning (risk scout's option 1). Its objections are met: the generated text is one line before the `#line` directive, so `authorLineOffset` stays a constant, and the cache key gains the layout.
- [init] Field types are restricted to `float`, `int`, `uint`, `float2`, `float4`; `bool` and `choice` are `uint`, color is `float4` — rejected `float3` because its padding (16/16 vs `packed_float3` 12/4) is the classic drift ([WebKit](https://lists.webkit.org/pipermail/webkit-changes/2023-June/287593.html), [Apple forum](https://developer.apple.com/forums/thread/64057)).
- [init] One field list drives both the MSL text and the packer (`EffectParameterLayout`, an Entity value like `DispatchGrid`), because the UseCase (packer) and the DataSource (source assembly) may not import each other — rejected a table per side, which is the drift this design exists to prevent.
- [init] A zero-parameter effect binds a 16-byte zero block, so the Metal gateway has no branch (`scripts/check-live-thin.sh`) — rejected a skip-when-empty check, a branch in a coverage-ignored module (`setBytes` of length 0 is invalid).
- [init] `setBytes` capped at 1 KB (32 parameters) — rejected an `MTLBuffer` ring: Apple documents raw-bytes binding up to 4 KB, copied at encode time, so no lifetime exists to manage ([MTLComputeCommandEncoder](https://developer.apple.com/documentation/metal/mtlcomputecommandencoder.md)).
- [init] Parameter panel is a separate window (`PickerWindow` precedent), opened from the menu — rejected a slider inside the menu because `MenuBarExtra` uses `.menu` style (`HostApplication.swift`), which draws an `NSMenu`; rejected `.window` style because it would redo the whole menu. Spike S2 is dropped.
- [init] Snap and clamp in pure Swift, never rely on the control — a `Slider` `step` regression is reported on iOS 26 ([thread 801416](https://developer.apple.com/forums/thread/801416)); unconfirmed on macOS, and pure clamping is needed for stored values anyway.
- [init] `ColorPicker` keeps `supportsOpacity` at its default — a macOS 26.0 layout crash is reported with `false` ([thread 800693](https://developer.apple.com/forums/thread/800693)); unconfirmed.
- [init] Health is judged in `EffectCatalogUseCase` (pure `EffectHealthPolicy`, sibling type), fed by a pass-outcome stream from `EffectRuntimeRepository` — rejected the pipeline (no failure memory by design, must not learn that effects exist) and the state DataSource (policy does not belong below the Repository). Outcomes carry the identity stamped at admission, so effect B never inherits a late failure of effect A.
- [init] Counted against an effect: `timeout`, `pageFault`, `outOfMemory`, `unknown`, `accessRevoked`. Not counted: `compileFailed` (already final and shown), `invalidResource`, `internalError` (the runtime's, per `EffectFailure`'s own doc). `GPUTiming` of zero means no data, never fast.
- [init] Breaker: consecutive count, cool-down, one half-open trial, any trial failure reopens with a doubled cool-down ([Fowler](https://www.martinfowler.com/bliki/CircuitBreaker.html), [Microsoft](https://msdn.microsoft.com/library/dn589784.aspx)). `timeout`, `pageFault` and `accessRevoked` never self-retry — a retried hang stalls the user's call again; those need an edit or an explicit re-enable (Q7).
- [init] The disabled record is keyed by effect id plus a source fingerprint, so an edit re-enables and a record is replaced rather than accumulated; it is written before the runtime is switched away, so a launch loop cannot repeat — rejected id alone, which leaves a fixed shader disabled.
- [init] No new module where an existing one fits: parameter and health policy go in `EffectCatalogUseCase`, presenters in `Presenters`, windows in `AppRouter`, views in `Views`. New targets arrive only through their own issue, because `Package.swift` is a hot file.
- [init] Spikes: S1 (block reaches the kernel) lands as the GPU smoke test of the binding issue; S3 (GPU timing is real) is a task; S4 (hang behaviour) is `hk:later`, VM lane only, never on the development machine.
- [init] Contract epic (ABI and seams) is built by an orchestrator-tier worker — it crosses about ten files and fixes what every Haiku contract copies; every other issue is Haiku under a narrow contract (Q5).
- [init] Worker PRs merge to a non-default branch, so GitHub's closing keywords do not fire: the worker closes its issue itself after merging.
- [run] Workers run as subagents of the orchestrator's Workflow scheduler (`isolation: worktree`, Haiku), which starts each issue the moment its blockers merge — rejected jam squads for this run: a jam session starts in the owner's default permission mode and stalls on a prompt nobody answers, while a subagent inherits the orchestrator's mode; the scheduler is also the pull loop, with no idle squad to feed. Reply "jam で" to switch.
- [run] Breakdown: every epic was drafted, then checked by its own verifier and by one cross-epic critic (unknown keys, cycles, files created twice, GOALS lines no issue serves); the critic added three issues (E11). New modules arrive through one task, S-TARGETS, that alone edits `Package.swift` and the lint allow-lists — rejected letting each epic add its own targets because `Package.swift` is a hot file every such issue would conflict on.
- [run] A failed task gets one contract repair (a judgment agent on the orchestrator's model that edits the issue, never the code) and one Haiku retry; a second failure is held for the orchestrator — rejected raising the worker's model (the cause is almost always the contract, and a stronger worker fixes one issue and leaves the cause) and rejected unbounded retries.
- [run] The known gate flake (`MachLoopbackTests.swift:217`, about one full run in five) is fixed first, as its own task, by amplifying the leak check (64 failed registers, fewer than 32 new receive rights); until it merges a worker reruns the gate once when that is the only failure — rejected nesting the two real-port suites under one serialized parent alone: it removes this target's concurrency, but the snapshot is process-wide.
- [run] While the screen is locked a window cannot be captured (#97 at 02:50, `CGSSessionScreenIsLocked`), so a UI task lands on a green gate with its shot owed (`hk:shot-pending`), and the orchestrator captures and reads every owed screen once the screen is unlocked; a visual defect becomes a regen issue — rejected holding every UI task until morning, which idles the UI epics for the night when the image check only moves later and is not dropped. Reply "Q8 hold" to hold them instead.
- [run] A chosen camera format on macOS is kept by holding the device lock from `activeFormat` through `startRunning` until `stop()` (#357, answering #153): `AVCaptureSessionPresetInputPriority` is `API_UNAVAILABLE(macos)` and the format/preset exclusivity is documented for iOS only, while `lockForConfiguration:` is documented as the way to keep settable properties from changing automatically (MacOSX26.5.sdk `AVCaptureDevice.h`). The preset path takes no lock, since an unneeded lock degrades other apps on the same camera — rejected re-setting `activeFormat` after `startRunning`, which streams the preset's format first and rests on nothing documented. Whether macOS keeps the format is checked on the device by a person.
- [run] A test that only outgrows its time limit under CI load (the lease-coverage property: 4.6 s locally, past 60 s in a parallel run with coverage on, on #154, #186 and #214) moves to a suite of its own with a longer limit (`Host absence, path coverage`, three minutes; #373, PR #377), and the hang-guarding suite keeps its one minute — rejected a longer limit on the test alone, since Swift Testing applies the shorter of the suite's and the test's limits, and rejected re-running failed jobs, which hides the next real hang behind the same symptom.
- [run] A UI PR embeds its screenshot through the commit that added it (`blob/<sha>/docs/shots/<n>/…`), not through `task/<n>`: the squash merge deletes the branch and a branch link then shows a broken image in the PR for good (WORKER.md step 5, found on #97) — rejected keeping the branch after merge, which leaves one stale branch per UI task.
- [run] #97 was held for a missing Screen Recording permission, but the cause was the lock alone: once the screen unlocked (07:56), the same process captured the gallery window, so the orchestrator finished the held task from its green worktree (PR #416). A repair judged while the screen is locked does not blame the permission without checking `CGSSessionScreenIsLocked` first.
- [run] The screenshot slot of `scripts/gallery` is `flock(2)` on fd 9, taken through `/usr/bin/python3` since macOS ships no flock(1): the kernel drops it with its last holder, so a gallery killed even by SIGKILL strands nothing (PR #416, from Copilot's review) — rejected the `mkdir` + pid slot, which a kill between the two steps leaves ownerless forever and whose stale-holder reclaim can delete a live owner's slot. `scripts/gate` keeps its `mkdir` slots for now: with five of them a stranded slot lowers concurrency without stopping it, and none was stranded in over a hundred gate runs; move it to `flock` the first time one is.
- [run] Workers gate through a detached helper that writes a log and a waiter that answers green, red, died or still running within one Bash call, five workers at a time on 3 gate slots (run 3, 2026-11-11): eight workers on 5 slots drove the load average past 100, every gate overran the 600 s a Bash call allows, and the harness kept each timed-out gate running in the background, so the old rule to run it again stacked gates until all nine first attempts timed out with nothing pushed — rejected a longer timeout (600 s is the ceiling) and fewer slots alone (a timed-out call still leaves its gate running).
- [run] A `codecov/patch` still pending after every other check passed does not block the merge (PR #432, 2026-11-11): its upload was queued at 07:13Z and Codecov had not answered half an hour later, while `gh pr checks --watch` kept the worker waiting on a check nothing requires. A failing codecov check stays red; a stalled one is re-kicked by re-running the PR's `test` job, which uploads the coverage again.
- [run] A worker that reopens its work as `task/<n>-r1` closes the PR it replaced (PR #442, 2026-11-11): step 7 said to open a new PR after a conflict and nothing about the old one, so #325, #320 and #442 stayed open beside the PRs that merged their issues until the orchestrator closed them.
- [run] A contract that adds no unit tests drops the generic Done line "every Interface item has a unit test named after its spec sentence" (#228, PR #467, 2026-11-11): five view and wiring contracts (#168, #170, #228, #232, #357) said both, the #228 worker followed the Done line and wrote a file of tests that evaluate `View.body`, and CI's whole `test` job went silent two seconds in until it was cancelled 30 minutes later, past the suite's `.timeLimit`. The same branch without that file passed (PR #473); body evaluations merged elsewhere pass CI, so the stall is in that file and is not shown to be the body evaluation itself. The repository rule already says SwiftUI view bodies are not unit-tested; where a running worker had already written such a test, the orchestrator removed the file from its PR branch (PR #473, #474) instead of stopping the run, and #478 removes the ones merged earlier.
